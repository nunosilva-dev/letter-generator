## Build and run

The [example ZIP](/downloads/letter-generator-examples.zip) already contains all four programs and their resources. In the extracted directory:

```sh
mvn package dependency:copy-dependencies
java -Djava.awt.headless=true -cp 'target/classes:target/dependency/*' FluentQuickstart
```

Use `TypedQuickstart`, `JsonQuickstart` or `HtmlQuickstart` for the other routes. Windows uses `;` between classpath entries. Each writes `letter.pdf`, or the first supplied argument. The parent directory of a chosen output path must exist.

## What happens at each step

1. Authoring creates content and styles. The typed/JSON routes supply the immutable model structure explicitly.
2. `build()` resolves builder configuration into a document; it does not generate PDF bytes.
3. `generate(...)` prepares themes/components, validates input and performs real pagination/layout.
4. `Files.write(...)` belongs to your application; the library itself returns owned PDF bytes.

Use `generator.render(document)` when you need the actual page count and diagnostics. Reuse the generator across calls; use a fresh mutable builder for each authoring operation. Invalid input or rejected layout throws without returning a partial PDF.
